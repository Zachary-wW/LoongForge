🚀 Quick Start

YAML-driven, five steps from install to launch.

Docker is the recommended path — a single image bundles CUDA/XPU toolchains, the patched Megatron submodule, and TransformerEngine, so every developer and every node trains from the same environment. Source install is also fully supported for advanced setups.

$ # NVIDIA GPU (Docker) git clone --recurse-submodules https://github.com/baidu-baige/LoongForge.git docker build --build-arg COMPILE_ENV=hopper --build-arg ENABLE_LEROBOT=false \ -t loongforge:latest -f ./LoongForge/docker/Dockerfile . $ # Kunlun XPU (Docker) docker build --build-arg BASE_IMAGE=loongforge/loongforge_kunlun:py310_torch25 \ --build-arg ENABLE_LEROBOT=false \ -t loongforge-kunlun:latest -f LoongForge/docker/Dockerfile.xpu .

Source install (uv pip install -e ".[gpu]" + python setup_env.py --te-tag v2.9) and full build-arg matrix: see NVIDIA install guide · Kunlun XPU install guide.

LoongForge decomposes every multimodal model into three interchangeable parts — vision encoder, projector, and language backbone — and wires them together declaratively in a single Hydra YAML. Swapping a ViT, projector, or LLM is a one-line config change, with no Python edits and no touching distributed code. Mainstream open-source models are already built in — DeepSeek, Qwen / Qwen-VL, LLaMA, InternVL, ERNIE4.5-VL, LLaVA-OneVision, MiniMax, GLM, WAN, Pi0.5, GR00T and more; browse configs/models/ for the full list of ready-to-use YAMLs.

# configs/models/qwen3_vl/qwen3_vl_30b_a3b.yaml defaults: - ../../models/image_encoder@model.image_encoder: qwen3_vit - ../../models/image_projector@model.image_projector: qwen_mlp_adapter - ../../models/qwen3@model.foundation: qwen3_30b_a3b - _self_ model: model_type: qwen3_vl ... # Swap the language backbone — one line change: - - ../../models/qwen3@model.foundation: qwen3_30b_a3b + - ../../models/deepseek3@model.foundation: deepseek_v3

LoongForge preserves Megatron-LM's native argument style — training phase, sequence length, batching, parallel strategy — so existing Megatron users have zero learning cost. On top of that, Hydra overrides let you configure each component independently: different TP / PP / EP sizes for the vision encoder vs. the language backbone, and flexible freeze switches per component. This is what enables truly heterogeneous parallelism inside a single multimodal training job.

TRAINING_ARGS=( --training-phase sft --seq-length 32768 --micro-batch-size 1 ... ) MODEL_PARALLEL_ARGS=( --tensor-model-parallel-size 1 --pipeline-model-parallel-size 2 --expert-model-parallel-size 8 ... ) # Per-component overrides (Hydra): different TP / freeze per component +model.image_encoder.tensor-model-parallel-size=1 +model.foundation.tensor-model-parallel-size=4 +model.image_encoder.freeze=True

LoongForge speaks both directions of the checkpoint world. You can load HuggingFace weights directly — point --load at an HF model directory and LoongForge handles the rest, with no offline conversion step. During training, high-performance native checkpoints are written at intervals. And when the run finishes, a single --save-hf flag exports back to HF format, keeping you compatible with the downstream inference / evaluation ecosystem out of the box.

TRAINING_ARGS=( --load $CHECKPOINT_PATH # point directly at the HF model directory --save $CHECKPOINT_PATH # high-performance training checkpoints --save-interval 40 --save-hf true # export HF weights on finish --save-hf-path /path/to/output ... )

Every supported model family ships with a ready-to-run launch script — pre-tuned parallel strategy, dataset wiring, MoE args, logging, the works. Pick a script from examples/ (NVIDIA GPU) or examples_xpu/ (Kunlun XPU), fill in your data and checkpoint paths, and launch. Below is the core launcher pattern shared by every example.

$ # e.g. examples/qwen3_vl/finetuning/sft_qwen3_vl_30b_a3b.sh PYTHONPATH=$MEGATRON_PATH:$LOONGFORGE_PATH:$PYTHONPATH \ torchrun --nproc_per_node 8 --nnodes $NNODES \ $LOONGFORGE_PATH/loongforge/train.py \ --config-file $LOONGFORGE_PATH/configs/models/qwen3_vl/qwen3_vl_30b_a3b.yaml \ "${DATA_ARGS[@]}" "${TRAINING_ARGS[@]}" "${MOE_ARGS[@]}" "${MODEL_PARALLEL_ARGS[@]}" \ +model.image_encoder.freeze=True
